## Human decisions recorded for T03 (2026-10-01)

### MVP trade-off: the list is ordered and bounded in memory

Approved. `SqlIntakeStore.ListCasesAsync` orders newest first by the case's
immutable `CaseCreated` audit instant, with the opaque case identifier as a
stable tie-break. **It currently reads every case-created selector/instant pair
of the firm, then sorts and bounds them in memory**, and only then reads the
name and stored tax year of the selected cases. Both queries lead with the
firm. This differs from the architecture's "reading `maximumCases + 1` rows":
the cost grows with the firm's total case count, not with the bound. It is an
accepted trade-off for the local MVP, not a scalable design. No migration or
schema change was required or made; a creation column with a firm-leading
index is the obvious later change if a firm's case count makes this matter.

### The handler and shared render-helper refactor

Approved, provided existing GET responses are unchanged except for the
approved notice path. `ExtractionEndpoints.ListAsync` and `ReviewAsync` now
delegate to `RenderListAsync` and `RenderReviewAsync`, which the two refusal
branches also call. The GET routes pass `WorkflowNoticeKind.None` and no
status code. The refusal tests assert that a refusal page equals the same page
as rendered by the GET before the refusal, plus only the notice.

### AC-78 reading

Confirmed: a refusal re-renders the same authorized page from stored state and
adds only the fixed notice. Nothing the caller posted is reflected. Box 12 is
never stored or rendered either way.
