## What T05 delivers

### Production adapter (`src/DocumentIntelligence/Production/`)

- `AzureDocumentIntelligenceOptions` — the validated binding: HTTPS
  `*.cognitiveservices.azure.com` custom subdomain on 443 matching the resource
  ID's account name, `canadacentral`, exactly `2024-11-30` / `prebuilt-layout`
  / `keyValuePairs`, a user-assigned managed identity GUID, a source bound
  ≤ 500 MiB, 1–5 attempts, an operation deadline ≤ 5 min and a cleanup budget
  strictly inside it. Anything else throws one fixed message.
- `AzureDocumentIntelligenceProvider` — implements the unchanged three-method
  port. User-assigned `ManagedIdentityCredential` (no retries, SDK logging and
  tracing off); `SocketsHttpHandler` with no redirects, cookies, proxy or
  activity propagation and an infinite client timeout (deadlines are token-owned).
  Each call first asks the host's `IExtractionAvailabilityGate`.
- `AnalyzeOperationLifecycle` — bounded source read (no truncation: over the
  bound refuses before any request); **one** `POST …/prebuilt-layout:analyze?
  api-version=2024-11-30&features=keyValuePairs`; the `Operation-Location` is
  validated (same origin, model path, exact query, non-empty UUID) and
  **reconstructed**, never followed; polling continues until the operation
  deadline while `running`/`notStarted`, and only transient read failures
  (429, 408, 5xx, transport) consume the exponential retry bound; immediate
  transformation; `DELETE` of the result within a reserved cleanup budget
  linked only to the total deadline, so caller cancellation cannot shorten it.
  Only an explicit `204` releases a result. Exhausted deletion emits the fixed
  `TaxAI-DocumentIntelligence-Lifecycle` event 1 (no payload) and releases
  nothing. Source and response buffers are zeroed; nothing is persisted.
- `DocumentLayoutRecognition`, `LayoutResultInterpreter` — the verified CRA T4
  (25) slip-face interpretation below.

### Verified identity

The printed slip face (S2, S3) carries the designator **`T4`** and both titles,
**`Statement of Remuneration Paid`** and **`État de la rémunération payée`**;
the e-text (S4, S5) renders them as `T4 - Statement of Remuneration Paid` and
`T4 - État de la rémunération payée`. Recognition requires the `T4` designator
token (not `T4A`, `T4 Summary`…), exactly one English and/or one French title,
no `Summary of Remuneration Paid` / `Sommaire de la rémunération payée`, **and**
at least one printed slip-face box field. A repeated title (the printed sheet
repeats the slip for two recipients) refuses rather than choosing one.

### Tolerance (presentation only)

Unicode compatibility form, letter case, apostrophe and dash variants, the
slash/colon/parenthesis punctuation of the printed labels, and whitespace; the
English and French label alone or together in either order; a printed box
number before or after the label, or `Box`/`Case NN`. Words are never
changed, dropped or substituted. A number contradicting its label, or an
explicit `Box`/`Case` number not printed on the slip face, refuses.

### Preserved application semantics

2025-only attribution, Box 12 handling, Box 45 required and Box 54 not required
on an employee copy all remain the existing parser's decisions; the adapter
only copies what is printed. The real-workflow test proves a bilingual employee
copy with no Box 54 passes the existing chain with **no** engine error, and the
same fixture without Box 45 fails (mutation check performed).

   `Microsoft.CognitiveServices/accounts/FormRecognizer` data actions (Learn,
   "Azure permissions for AI + machine learning") list
   `documentmodels:analyze/action`, `documentmodels/analyzeresults/read` and
   `info/read`, but **no explicit analyze-result delete action**. The custom
   role grants `documentmodels/analyzeresults/*`; whether that authorizes
   `DELETE` must be observed by DEP-12. If it does not, deletion fails closed
   (no result is released) and the role needs a plan-approved change.

   separate Analyze operations, as the architecture states; each is deleted.
